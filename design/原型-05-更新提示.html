原型 05 · 更新提示

修复目标：v0.2.5 中出现「发现新版本」提示时，竖排 Dock 窗口被压扁、文本被截断（见缺陷截图）。 本页定义横排与竖排两种停靠下的更新提示布局，以及 S1–S4 四个状态的内容与按钮； 交互与文案与 DockViewModel 的更新状态机一致：检查 → 下载（可取消）→ 二次确认安装 / 打开发布页。

交互演示 · 点「下载」体验完整状态机
演示可交互：切换 S1–S4、点「下载」看进度；停靠边可切到左/右查看竖排形态。通知类反馈（下载完成等）走 Toast，见原型 08。
布局规范
  • 横排（上/下边缘）：更新条是 Dock 面板内的一行，位于图标区下方；min-width:330px，面板宽度取「图标区 + 工具区」与更新条的较大值；更新条永远不反向压缩图标区。
  • 竖排（左/右边缘）：Dock 宽度不变，只在工具区下方追加 新版本 胶囊（强调色描边 + 呼吸圆点）；点击胶囊弹出 290px 更新卡片，锚在 Dock 内侧（左停靠 → 卡片在右；右停靠 → 卡片在左），垂直中心与胶囊对齐。
  • 文本：单行，超出省略号；版本号加粗；按钮恒靠右，不换行、不换列。
  • 给 Avalonia 的实现注记：窗口是 SizeToContent，更新条内部禁止使用星号（*）列——星号列在按内容测宽时塌缩为 0，正是把整窗压扁的原因；文本区用固定/最大宽度 + 截断，按钮用 Auto 列。

横排 Dock（上边缘）· 四状态

S1发现新版本 —— 主按钮「下载」（有匹配资产时）+ 次按钮「忽略」；忽略后本次运行不再提示。
S2下载中 —— 文本行下方 4px 进度条（强调色），按钮只剩「取消」；下载期间忽略按钮隐藏。
S3已就绪 —— 图标转成功色，主按钮变「安装」（非 Windows 安装包资产时为「打开安装包」）+「忽略」；点击安装后由系统安装器接管，程序退出。
S4没有匹配资产 —— 找不到当前系统/架构的下载资产时降级为「打开发布页」，避免下错文件。

竖排 Dock（左边缘）· 胶囊 + 弹出卡片

S2竖排时 Dock 只出现「● 新版本」胶囊（呼吸点提示），Dock 宽度不被更新内容撑开；点击胶囊在 Dock 内侧弹出卡片。
S3右边缘对称：卡片弹在 Dock 左侧。卡片内容与横排更新条一致（S1–S4 同一套状态机）。
状态机与文案（与 DockViewModel 对齐）
  • S1 文本 发现新版本 v0.2.5；按钮 下载（AssetUrl 与 ChecksumUrl 均存在时）/ 忽略。
  • S2 文本 正在下载 v0.2.5 · 45% + 进度条；按钮 取消。Toast 同步「正在下载更新 · 45%」。
  • S3 文本 v0.2.5 下载完成；按钮 安装 / 打开安装包（按资产是否为 *-setup.exe）+ 忽略；Toast「下载完成，请点击安装」。
  • S4 文本 发现新版本 v0.2.5 · 没有匹配当前系统的安装包；按钮 打开发布页 + 忽略。
  • 下载失败 → Toast「下载失败，请重试」，回到 S1；取消 → 回到 S1。
